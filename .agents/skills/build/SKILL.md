# Build — 핵심 기능 구현

1. `SPEC.md`의 필수 요구·인수 조건·실행 환경·현재 미완료 항목을 확인한다. 미확정의 중요한 업무 규칙만 사용자에게 넘긴다. 다른 단계의 승인을 반복 요구하지 않는다.
2. FE·BE가 함께 필요하면 먼저 확정된 계약 버전과 성공·오류 예를 확인한다. 각 역할에 AC, 읽을 자료, 쓰기 가능한 경로(테스트 포함), 기대 증거를 전달한다. 병렬 실행이 허용되고 소유 경로가 독립적일 때만 동명의 서브에이전트를 사용한다. 그 외에는 메인 세션이 `$backend`와 `$frontend`를 순서대로 적용한다.
3. **가장 작은 실제 실행 경로**(입력 → 처리 → 출력, 웹이면 UI → API → 상태/데이터 → UI)를 구현한다. 계산·분기·경계 조건은 실패 테스트를 먼저 실행하고 최소 구현으로 통과시킨다. 계약 변경이 필요하면 관련 구현을 멈추고 부모가 수정한 계약을 양쪽에 전달한다.
4. 부모가 결과를 합쳐 기존 스택의 서버를 실행하고 실제 BE로 핵심 흐름을 확인한다. 사용자에게 내장 Browser에서 직접 확인할 경로와 조작을 안내한다. 관찰한 범위와 남은 확인 사항을 `docs/verification.md` 또는 기존 검증표에 남긴다.
5. 중요한 선택과 실제 사용자 판단은 `$explain`으로 남긴다. 로컬 커밋과 프롬프트 기록은 AGENTS.md의 분리 규칙을 따른다.
6. 실패가 반복되면 최소 재현, 가능한 원인과 영향, 빠른 대안을 비교한다. 요구사항 의미를 바꾸는 해결책만 승인받는다. 시간이 부족하면 선택 기능을 접고 필수 경로를 완성한다.

금지: 외부 데이터 전송, Git Push, 감독·제출 자동화, 허용되지 않은 브라우저 Computer Use, 통과시키기 위한 근거 없는 기대값 수정.
