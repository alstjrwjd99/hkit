# Finish — 제출 전 최종 점검

1. 실제 남은 시간을 확인한다. 종료 약 30분 전부터 필수 누락·고장·문서 상태에 집중하고, 10분 전부터 제출을 준비하는 것을 권한다. 실제 플랫폼 타이머가 우선이다.
2. 코드·필수 산출물과 SPEC의 요구 ID를 다시 대조한다. 프로젝트의 실제 실행 명령을 시도하고, 가능한 빌드/테스트/핵심 API 확인을 수행한다. 서버/화면 확인은 사용자 직접 수행과 AI 검증을 구분한다.
3. `EVIDENCE.md`에 재실행 방법, `docs/verification.md`와 `docs/decision-log.md`(또는 기존 기록)의 위치, 남은 한계를 적는다. 필수 AC에 실패·미검증이 있으면 그 상태로 인계한다. `$explain`을 활용해 실제 선택과 관찰값을 사용자에게 설명한다.
4. 사용자가 제출 전에 자신의 말로 설명할 수 있는지 세 가지 축만 점검한다: (a) 입력→처리→출력 (b) 중요한 결정 1~2개와 근거 (c) 검증 근거와 남은 한계. 사용자가 요청할 때만 이 단계에서 짧은 예상 점검 질문을 제시한다.
5. 필수 파일의 경로·실제 저장·과제 지정 형식, 환경변수, 큰 임시 파일과 비밀정보, Git 상태를 확인한다. 결과물을 강제로 밀어 넣거나 사용자 확인을 대신하지 않는다.
6. **사용자가 제출물을 확정한 순간부터 AI 지원을 중단한다.** 이후 후속 서술형 6문항(문항당 5분)은 AI·복사/붙여넣기 금지이므로 질문 답변·수정·대본 생성·첨삭 등 지원하지 않는다. 제출 버튼과 후속 화면 조작은 사용자 몫이다.
