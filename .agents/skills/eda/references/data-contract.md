# 데이터 계약 v1

과제에서 기존 스키마를 운영하면 그 정의를 우선하고 아래 필드와 근거를 연결한다. 신규 과제는 프로파일러의 `--contract-out`으로 초안을 만든다. 출력 폴더를 먼저 만들고, 파일이 있으면 새 리비전 경로를 쓴다.

## 필드와 확정

| 필드 | 의미 |
|---|---|
| `schema_version` | 이 규격은 정수 1 |
| `status` | `draft` 또는 부모가 검토한 `confirmed` |
| `revision`, `prd_revision` | 데이터 계약과 연결된 PRD의 리비전. 확정 전에 둘 다 채운다 |
| `source` | 원본 경로·바이트 SHA-256·구분자 |
| `observations` | 인코딩, 조사 범위, 열별 타입·결측률·숫자 범위·날짜 검사, 키 후보 등 프로파일러 출력 |
| `constraints` | 요구와 근거가 있는 입력 제약 목록. 초안 기본값은 빈 배열 |

관찰된 최솟값·최댓값, 결측률 0, 키 후보는 조사 범위의 사실이다. 입력 허용 범위·필수 여부·고유성은 과제 요구와 연결해 부모가 별도로 확정한다. 타입 추정은 샘플에 의존하며 `mixed`·`unknown`도 유효한 결과다. `complete_scan=false`이면 전수 조사로 보고하지 않는다. 숫자 범위 값은 정밀도를 보존하는 십진 문자열이며, 공백과 선행 0을 포함한 식별자 정규화는 별도 업무 규칙이다.

## 제약 항목

각 항목은 `id`, `status`(`proposed`/`confirmed`), `columns`, `rule`, `parameters`, `ac_ids`, `evidence`를 가진다. `ac_ids`와 `evidence`는 문자열 배열이다. 근거는 요구 위치 또는 재현 결과의 파일·행 ID로 연결한다.

| rule | columns | parameters |
|---|---|---|
| `required` | 열 하나 | `{}`. 필드·열 누락과 빈 문자열·공백을 누락으로 판정 |
| `type` | 열 하나 | `{"type":"integer"}`. integer/number/boolean/string 중 선택. 수치 타입은 유한 값으로 제한하고 기존 API의 파싱 규칙과 연결 |
| `range` | 열 하나 | `{"min":"0","max":"100"}`. min/max 중 하나 이상, 양끝 포함, 단위는 PRD에 명시 |
| `date_format` | 열 하나 | `{"format":"%Y-%m-%d"}` 또는 iso8601 |
| `unique` | 단일·복합키 열들 | `{}`. 누락 허용 여부는 required로 정의 |

예를 들어 PRD의 R1-AC2에서 음수 수요를 거부하도록 확정했다면 다음 제약을 추가할 수 있다. 숫자는 제약 형식을 설명하기 위한 예다.

```json
{
  "id": "D-R1",
  "status": "confirmed",
  "columns": ["demand"],
  "rule": "range",
  "parameters": {"min": "0"},
  "ac_ids": ["R1-AC2"],
  "evidence": ["docs/prd.md#R1-AC2"]
}
```

누락 값의 허용과 변환은 API 계약에 따라 처리하고, BE가 해당 조건을 테스트로 고정한다. 제약은 원본 데이터를 정제하거나 수정하는 명령을 포함하지 않는다.

행 격리·중복 처리·관측 단위·KPI의 0분모처럼 업무 의미가 필요한 처리 정책은 PRD·API 계약에 정의하고, 데이터 계약 리비전과 함께 BE 시나리오에 연결한다.

## BE 소비와 변경

부모는 제약별 근거·타입·누락 처리·테스트 기대값을 검토해 계약 리비전을 확정한다. BE는 현재 PRD와 연결된 `confirmed` 계약의 `confirmed` 제약만 구현 규칙으로 사용한다. 지원하지 않는 규칙·열·버전이나 비어 있는 AC/근거는 부모에게 전달하고 관련 검증 완료를 보류한다.

BE는 계약을 읽어 기존 프레임워크의 입력 검증과 연결하거나, 생성한 검증 코드가 계약과 같은 리비전인지 테스트로 대조한다. 각 제약에 정상·위반·경계 시나리오를 연결한다. `observations`는 테스트 데이터와 분석 판단의 근거로 사용한다.

PRD의 가설·KPI 산식·분모·입력이 달라지면 영향을 받는 분석과 제약을 재검토한다. 부모가 새 리비전을 배포하고, BE가 기존·신규 규칙을 대조해 관련 테스트를 다시 실행한다. 기존 확정 계약을 프로파일러 출력으로 덮어쓰지 않는다.
