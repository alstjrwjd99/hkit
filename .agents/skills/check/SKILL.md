# Check — 검증 및 증거 확인

1. SPEC의 필수 요구 R1…Rn과 과제 지정 산출물 목록을 읽는다. 실행 중인 코드를 먼저 파악하되 모든 파일을 다시 통째로 읽지 않는다.
2. 요구별로 `실제 코드 위치 → 검증 방법 → 명령/절차 → 관찰 결과 → 판정`을 만든다. 기존 테스트·빌드·타입 검사·API 호출을 실행하고 결과를 기록한다. 테스트가 없으면 핵심 위험을 검증하는 최소 사례를 제안하거나 추가한다.
3. 검증 계층을 정확히 구분한다: (a) 정적 검사 (b) 단위 테스트 (c) API·로컬 통합 (d) 실제 사용자 흐름 수동 확인 (e) 미실행. `curl` 200은 UI E2E 통과를 증명하지 않는다.
4. UI 화면 검사는 Cofa 내장 Browser를 사용자가 직접 수행하도록 포트·경로·동작 2~3개를 안내한다. **AI 브라우저 자동 조작/Computer Use를 실행하지 않는다.** 과제 규정이 허용한다고 명시한 별도의 자동 테스트 실행만 고려한다.
5. 핵심 정상 사례 1개, 실패/경계 사례 1개 이상을 우선 검증한다. 잘못된 입력, 누락 값, 중복, 인증/권한, 데이터 무결성, 기초 성능 등은 과제에 직접 관련된 것만 고른다. 수치·판정의 핵심 기대값은 구현 코드 외부의 원자료·독립 계산과 대조한다.
6. 코드 수정 전 실패를 재현하고 같은 조건으로 재실행한다. 테스트 기대값을 결과에 맞추거나 mock만 통과시키고 실제 통합 검증이라고 적지 않는다.
7. `EVIDENCE.md`에 실제 출력·명령을 기록한다. 근거 없는 `PASS`를 찾아 `미검증` 또는 `FAIL`로 바로잡고, 가장 심각한 문제 3개만 우선순위대로 보고한다. 사용자 요청이 '읽기 전용 리뷰'라면 수정하지 않는다.
